# «Пушкин. Живой» — код для Tilda

Четыре вставки. Порядок важен: сначала HEAD, потом стили, потом блок, потом футер.

| Файл | Куда вставлять в Tilda |
|---|---|
| `01-head.html` | Настройки сайта → **Ещё** → HTML-код для вставки внутрь **HEAD** |
| `02-styles.css` | В блок **T123** на странице, обернув в парный тег `style` (или туда же, в HEAD) |
| `03-body-t123.html` | Блок **T123 «HTML-код»** на пустой странице |
| `04-footer.html` | Настройки сайта → **Ещё** → HTML-код для вставки в **BODY** (перед `</body>`) |

Страницу лучше делать пустой: без стандартной шапки и подвала Tilda —
они уже есть внутри блока.

## Что в каждом файле

**01-head.html** — шрифты с CDN плюс `preconnect` и `preload`, весит 2 КБ.
Если не хотите зависеть от стороннего CDN, возьмите вместо него
`01-head-embedded.html`: там те же шрифты вшиты в base64 (88 КБ),
и грузить вообще ничего не нужно.

**02-styles.css** — вся вёрстка и анимация. В самом начале, в блоке `.pz`,
**один раз** перечислены все 15 картинок (`--img-…`). Больше нигде адресов нет.

## Раздача файлов — jsDelivr

Своего хранилища у Tilda нет, поэтому картинки и шрифты раздаёт **jsDelivr** —
публичный CDN, который отдаёт файлы прямо из GitHub-репозитория. Ничего
настраивать и никуда загружать не нужно: репозиторий публичный, файлы уже в нём.

```
https://cdn.jsdelivr.net/gh/dimrurnd-cell/Pushekb@КОММИТ/landing/img/pushkin-hero.jpg
```

Ссылки запинены на коммит ``da3345d``, поэтому
кешируются навсегда и не сломаются, если файлы в ветке потом поменяются.

**Как обновить картинку.** Положите новый файл в `landing/img/`, закоммитьте,
запушьте — и замените хвост после `@` на новый хеш коммита автозаменой
в `02-styles.css` и `01-head.html`. Строка одна и та же во всех ссылках:

```
6759bc79de70b93ecab46ae0270f3e118852ef08   →   новый хеш коммита
```

**Читаемые ссылки вместо хеша.** На GitHub (Releases → Create a new tag)
сделайте тег, например `assets-v1`, на нужном коммите — и подставьте его
вместо хеша: `…/Pushekb@assets-v1/landing/…`. Тег тоже кешируется навсегда.
Запушить тег из этой среды не получилось (пуш тегов блокируется), поэтому
сейчас стоит хеш.

**Если предпочитаете GitHub Pages.** После слияния ветки в `main` включите
Pages (Settings → Pages → Deploy from a branch → `main` / root) — файлы будут
доступны по `https://dimrurnd-cell.github.io/Pushekb/landing/img/…`.
Это тоже одна автозамена по двум файлам.

**03-body-t123.html** — разметка. Заполнить: всё, что в `[КВАДРАТНЫХ СКОБКАХ]`,
и `href="#"` у кнопок «Купить билет», «Смотреть трейлер», «Все проекты студии»
и ссылок в подвале.

Блоки страницы: первый экран · **01 О выставке** · Пролог · Три экрана ·
Оживление · Десять эпизодов · **05 Шедевры в фильме** · Зал ·
Голоса · **08 Расписание** · Как прийти · **09 Билеты** · Финал · подвал.
Структура и подача информации перенесены с выставки «Репин. Учитель великих»
(репозиторий `dimrurnd-cell/repin`) и переписаны под Пушкина.

## Ожившее фото на первом экране

В арке первого экрана лежит короткий ролик: Пушкин снимает шляпу и поднимает
взгляд.

Ролик собран по двум опорным кадрам, чтобы лицо не «уплывало». Первый кадр —
ровно `pushkin-hero.jpg`, то есть заставка и первый кадр видео совпадают. Последний
кадр собран отдельно: та же поза, тот же фон и сюртук, но шляпа поднята, а лицо
взято с эталонного портрета. Движение между кадрами сгенерировано моделью
**Wan 2.2 I2V** и смонтировано так, чтобы ролик заканчивался именно на эталонном
кадре — лицо в финале зафиксировано, а не додумано моделью.

Файл лежит в репозитории — `landing/video/pushkin-hat.mp4` (560×728, H.264,
без звука, 86 КБ) — и раздаётся с того же CDN, что картинки и шрифты:

```
https://cdn.jsdelivr.net/gh/dimrurnd-cell/Pushekb@6759bc79de70b93ecab46ae0270f3e118852ef08/landing/video/pushkin-hat.mp4
```

Ролик запускает сам браузер: `autoplay muted playsinline` — без звука, инлайном,
один раз, без повтора; останавливается на последнем кадре, где шляпа снята.
JavaScript для показа ролика не нужен — он только пробует запустить видео
повторно, если браузер заблокировал автозапуск. Пока файл грузится (или если
он вообще не загрузится), тег показывает `poster` — ту же фотографию, что и
на статичном первом экране, поэтому вид не ломается. При системном
«уменьшить движение» видео скрывается через CSS и остаётся фотография.

## Что нужно проверить перед публикацией

- **Расписание сеансов** — в блоке стоит пометка `[ПОДТВЕРДИТЬ РАСПИСАНИЕ
  ПЕРЕД ПУБЛИКАЦИЕЙ]`. Тринадцать сеансов с 11:10 до 19:10 перенесены с
  «Репина» как рабочая заготовка: формат тот же, фильм те же 40 минут.
  Реальные часы работы площадки я не знаю — подставьте свои и уберите пометку.
- Всё остальное в `[КВАДРАТНЫХ СКОБКАХ]`: адрес, часы, цены, вместимость зала,
  телефоны, имена артистов.
- В блоке «Билеты» оставлено место под виджет Яндекс.Афиши — как на «Репине».

**04-footer.html** — анимация. Чистый JS без библиотек, с jQuery Tilda не конфликтует.

## Что анимировано

- Первый экран: «ПУШКИН.» собирается по буквам, «Живой» **прописывается слева направо**,
  как от руки; портрет всплывает и медленно дышит, по нему проходит блик;
  фон и рукописные строки двигаются с параллаксом.
- Прокрутка: блоки всплывают снизу с задержкой друг за другом.
- Цифры 40 / 3 / 10 / 100+ **досчитываются** при появлении.
- Все фотографии медленно наезжают (Ken Burns) — только пока видны на экране.
- В прологе идёт снег.
- Плавающая шапка выезжает после первого экрана, снизу у неё **золотая полоса прогресса**.
- Карточки и плитки реагируют на наведение, кнопки заливаются золотом снизу вверх.
- Плавная прокрутка по якорям меню.

Если у посетителя в системе включено «уменьшить движение», скрипт всё выключает сам.

## Правки

Акцентный цвет и все остальные — вверху `02-styles.css` в блоке `.pz`
(`--gold`, `--ink`, `--paper`, `--night`). Меняются в одном месте.

## Проверка

Собрать одну страницу из всех четырёх вставок и снять скриншоты:

```bash
python3 _build_test.py   # соберёт _test.html
python3 _shot.py         # скриншоты на 1440 / 960 / 390
```

Проверено в Chromium на 11 ширинах от 320 до 2560 px: горизонтальной
прокрутки нет нигде, ошибок в консоли нет, все пять начертаний
шрифтов подгружаются. Ролик первого экрана при локальной проверке не
грузится — его адрес недоступен из среды разработки, это не ошибка вёрстки.

`_build_tilda.py` собирает ту же страницу в обёртках Tilda
(`#allrecords` → `.t-rec` → `.t123` → `.t-container_100`) и с её
глобальными стилями поверх наших, `_diff.py` сравнивает два рендера
по ключевым параметрам — так ловятся конфликты с темой сайта.

Проверка идёт по локальным файлам (`_build_test.py` подменяет CDN на
`../img/` и `../fonts/`) через локальный http-сервер — по `file://`
`preload` со шрифтами не проходит из-за CORS, это особенность протокола,
а не кода. Сами ссылки на jsDelivr из среды разработки недоступны
(закрыт исходящий трафик), поэтому сверены построчно с содержимым
коммита: все 15 картинок и 5 шрифтов на месте.
